# 文言を剥がす

設計は `docs/design-i18n.md`。ここは**手順**だけを持つ。

## 1 回ぶんの流れ

文言を 1 つ足す・直すたびに、この 5 つ。**面をまたいで一度に広げない**
——落ちたときに原因が追えなくなる。

```bash
# いま何が残っているか
W="/mnt/c/Program Files/nodejs/node.exe"
"$W" node_modules/vitest/vitest.mjs run src/lib/i18n
```

1. `ja.ts` にキーを足す
2. `en.ts` に同じキーを足す（**足し忘れは型で落ちる**）
3. 画面から `t('…')` で引く
4. 同じ語がすでにあれば、新しいキーを作らず**そちらへ寄せる**
5. `verify` スキルで 4 つ通す

## キーの付け方

**同じ語は 1 つのキーにする。**これが辞書を作る目的の半分。

```
common.*   どの面でも同じ意味で使う語（閉じる・推移を見る・今日・前へ・次へ）
<面>.*     その面にしか出ないもの（records.* / home.* / hero.* / badge.* …）
```

分けるのは**語が同じでも意味が違うとき**だけ。そのときは
`i18n.test.ts` の `SAME_WORD_OK` に**理由を書いて**通す（例：曜日の「日」と日数の「日」）。
書けば「なぜ 2 つあるか」がその場に残る。

### 記号を入れない

`＋` `・` `（）` `✓` は**見た目なので部品が持つ。**辞書に入れると、
「＋ プリセットを作る」と見出しの「プリセットを作る」が別のキーに分かれる。

```tsx
<Button adds>{t('preset.createTitle')}</Button>   // ＋ は Button の adds
（{t('settings.count', { n })}）                   // 括弧は見出しの飾り
```

読み上げには出さない（`aria-hidden`）。「プラス セットを追加」は要らない。

### 文を JSX で継ぎ足さない

強めたい語があっても、**前・語・後の 3 キーに割らない。**日本語では通るが、
**英語では順が変わる。**穴を開けて `Strong` に埋めさせる。

```tsx
<Strong text={t('checks.datesOnlyNote')} values={[t('checks.datesOnly')]} />
```
```ts
'checks.datesOnlyNote': '見るのは{strong}です。疲労の量は持ちません。'
'checks.datesOnlyNote': 'It reads {strong}. It does not model fatigue.'
```

値のまえに置く断片（`直近 ` ＋ 数値）も同じ。`'直近 {value}'` にする。

### 段階ごとに文を書かない

閾値・部位・指標ちがいの文を並べると、**同じ規則の中で言い方が割れる。**
実際にバッジは「7日ぶん記録」と「通算30日を記録」が並んでいた。
違う数は穴にして、文は 1 つにする。

```ts
'badge.days.detail': '{n}日ぶん記録'    // 125 キーが 46 になった
```

### 長さ

**事実だけ書く。**「なぜそうしているか」と「〜しないでください」は落とす。
目安は 30 字まで（`ja.ts` の平均は 11.5 字）。理由を残したいならコードのコメントへ——
読むのは作者で、画面に出す相手ではない。

### 組み立てない

`${a}と${b}` をコードに残さない。**英語では語順が変わる**ので、組み立てた場所を
すべて直して回ることになる。穴は辞書側に開ける。

```ts
'home.since': '{date} から {days}日間 · {recorded}日ぶん記録'
'home.since': '{days} days since {date} · {recorded} days recorded'
```

### 表から引くのは良い

配列の要素にキーを持たせ、`t(o.key)` で引く形は**許されている**
（型が `MessageKey` で、リテラルは表にあるので検査が効く）。
禁じているのは `` t(`x.${id}`) `` のように**文字列として組み立てる**場合だけ。

```ts
const SLOTS: { id: SlotId; key: MessageKey }[] = [
  { id: 'am', key: 'records.slotAm' },
  { id: 'pm', key: 'records.slotPm' },
];
```

## 検査が落ちたとき

`src/lib/i18n/i18n.test.ts` が見ているもの。**どれも設計どおりの落ち方**なので、
検査を緩める前に、まず自分の書き方を疑う。

| 落ちたテスト | 直し方 |
| --- | --- |
| 日本語に重複が無い | 同じ語を 1 つのキーへ寄せる。意味が違うなら `SAME_WORD_OK` に理由つきで |
| 重複の例外表が腐っていない | 解消した語を `SAME_WORD_OK` から消す |
| 使われていないキーが無い | **先走って足したキー**を消す。「あとで使う」で残さない |
| キーを組み立てていない | 表から引く形に直す |
| 英語に重複が無い | 日本語が分かれていても英語で潰れている。訳を直すか、キーごと統合する |
| 差し込む穴が…そろっている | `{n}` を片方の辞書に入れ忘れ。値が黙って消える |
| 英語に日本語が残っていない | 訳し忘れ。キーはあるので型では見えない |
| 値を空白で継ぎ足していない | `直近 ` のような断片。`{…}` の穴にする |
| 文を `<b>` で断片に割っていない | `Strong` と `{strong}` に直す（下記） |
| 文が句点で終わっている | 文として終わるものは `。` で閉じる |
| 剥がした面に日本語が残っていない | 剥がし漏れ。例外表に逃がさず、剥がす |
| 訳さない面の一覧に…残っていない | 理由が要らなくなったのに残っている。1 行消す |
| 英名がすべての種目にある | カタログに種目を足したら `catalogNames.en.ts` にも足す |
| カタログに無い種目の英名が残っていない | カタログから消したら英名も消す |

## NOT_TRANSLATED

剥がすのは**終わっている**（`NOT_YET` はもう無い）。残っているのは
**訳さないと決めた面**の表だけで、`i18n.test.ts` が持つ。

```ts
const NOT_TRANSLATED: Record<string, string> = {
  'src/lib/exerciseCatalog.ts': '種目名の日本語はここが基準（docs/design-i18n.md §4）',
  'src/lib/seed.ts': 'デモの初期データ。画面の文言ではない',
  'src/lib/perf.bench.ts': '開発者しか走らせない計測の見出し',
};
```

- リストに**無い**ファイルに日本語が残っていたら落ちる
- リストに**ある**ファイルから日本語が消えても落ちる

2 方向あるので腐らない。**増やすときは理由を書く**——書けないなら、それは剥がす面。

## たくさんある定義（バッジ・カタログ）

`badges.ts` のように**同じ形が 60 件並ぶ**ものは、1 件ずつ書き写さない。

- 定義側は `name` / `detail` をやめて **`nameKey` / `detailKey`（型は `MessageKey`）**を持つ
- キーは **id から機械的に**（`badge.<id>.name` / `badge.<id>.detail`）
- 辞書の行はスクリプトで生成する（`id` と元の文を抜いて `ja.ts` と `en.ts` に流す）
- **判定の値（閾値・条件式）は訳さない。**数え方は言語で変わらない

## 重複が出たら、まず日本語を疑う

`SAME_WORD_OK` に逃がす前に、**同じ日本語になっていること自体が正しいか**を見る。

実際にあった例：体組成側とトレ側の別々のバッジが、どちらも
「はじめて30日 / 最初の記録から30日」だった。英語では
`since your first record` と `since your first session` で区別していたので、
**日本語のほうを直した**（「トレはじめて30日 / 最初のトレーニングから30日」）。

例外表に入れるのは、**英語でも同じ語になる**か、**言語が違えば別の語になる**ことが
はっきりしているときだけ（曜日の「日」と日数の「日」）。

## 見落としやすいところ

検査を広げるまで、実際に漏れていたもの。

- **配列・表の中の文字列**（`{ label: '1週' }`）
- **中括弧が混じる地の文**（`最長 {n}日 · 通算 {m}日`）
- **`lib` に置いた画面用の定数**（曜日の文字）
- **`aria-label`**。読み上げにしか出ないので、画面を見ても気づけない
- **グラフの軸・凡例・表の見出し**（`charts/` と `DataTables`）
- **タブとトグルの名前**（`App.tsx` の切り替え・`TabBar`）。毎日見ているので、
  かえって文言として意識に上らない

## テストは日本語の端末で走る

既定は「端末に合わせる」で、jsdom の `navigator.language` は英語。
`src/test-setup.ts` で `ja-JP` に固定してある。**ここを外すと既存のテストが全部落ちる。**
英語で出ることを確かめたいテストは、その場で言語を名指しする。

## 種目名

種目名だけは**辞書に入れない。**日本語は `exerciseCatalog.ts` の `name` が基準で、
英名は `catalogNames.en.ts` の **ID → 英名**の表から引く。

```ts
exerciseName(t, exercise)   // 画面に出す名前。改名していればその名前のまま
otherLocaleNames(id)        // 検索で足す語（もう一方の言語の名前）
```

保存されている名前がカタログ名と一致すれば「改名していない」とみなして引き直す。
**別のフラグを持たない**——持つと、改名を取り消したときに古い印が残る。

カタログに種目を足したら、`catalogNames.en.ts` にも足す（忘れるとテストが落ちる）。

## 言語そのものが要るとき

`t` は `locale` を持っている（`t.locale`）。辞書に無いもの（種目名・日付の書式）は
ここから引く。**`locale` を別の引数で通さない**——途中の関数すべてに引数が 1 本増える。

```ts
const t = makeT('ja');   // 画面の外（試験・ErrorBoundary）で作るときはこれ
```

## 訳さないもの

- コード中のコメント・`docs/`・コミットメッセージ（読むのは作者）
- 週の始まり（日曜〜土曜）。**表示ではなく集計の単位**で、変えると過去の数字が変わる
- 小数点・桁区切り。打つ値と読む値をずらさない
