# 国際化 設計メモ

対象は **日本語と英語**。種目カタログとバッジも訳す。
表示言語は**端末に従い、設定で上書きできる**（テーマと同じ作法）。

---

## 1. 背骨

> **文言はコードから剥がす。計算の定義は動かさない。**

訳せるのは**読むもの**だけで、**数え方**は言語で変わらない。
週が日曜〜土曜であること、7 日移動平均であること、部位別セット数の数え方は、
ロケールに関係なく同じ値を出す（`docs/design-storage.md` の週レコードもこれに依存している）。

### 1.1 週の始まりは変えない

英語圏の暦は日曜始まりが多いが、月曜始まりの国もある。**それでも切り替えない。**

週は表示ではなく**保存と集計の単位**で（週ごとのレコード・週平均・週次の部位別セット数）、
変えると**過去の数字がすべて変わる**。「先週 -0.4kg」が言語設定で別の値になるアプリは、
数字の出どころを説明できない。README の「計算の定義」に「週＝日曜〜土曜」と書いてある。

### 1.2 依存は増やさない

`react-i18next` などは入れない。README の「ランタイムの依存は React だけ」を崩す。
辞書は素のオブジェクト、取り出しは小さなフック 1 つで足りる。

### 1.3 コメントと設計メモは日本語のまま

訳すのは**利用者が読むもの**だけ。コード中のコメント・`docs/`・コミットメッセージは
作者が読むもので、訳すと理由の密度が落ちる。

## 2. 辞書

```
src/lib/i18n/
  ja.ts     基準。キーと日本語
  en.ts     Record<Key, string>。**抜けは型エラー**になる
  index.ts  Locale 型・useT・辞書の選択
```

```ts
export const ja = {
  'records.save': '記録する',
  'goal.reached': '到達',
  'set.count': '{n} セット',
} as const;

export type MessageKey = keyof typeof ja;
export const en: Record<MessageKey, string> = { ... };
```

**基準は日本語。**`ja.ts` にキーを足して `en.ts` に足し忘れると、型で落ちる。
逆向き（英語基準）にすると、いま動いている日本語のほうが壊れる。

### 2.1 差し込み

`t('set.count', { n: 3 })` で `{n}` を差し替える。**語順は辞書側が決める**ので、
`${a}と${b}` のような組み立てをコードに残さない（英語では順が逆になる）。

### 2.2 キーの付け方 — **同じ語は 1 つのキーにする**

辞書を作る目的の半分は**文言をそろえること**にある。いま同じ語が別々の場所に
書いてあって、片方だけ直る余地が残っている（`プリセット` 6 か所、`セット` 6 か所、
`マイ種目` 5 か所、`非表示` 4 か所、`重量`／`部位`／`回数`／`秒数` 各 3 か所）。

```
common.*   どの面でも同じ意味で使う語
           編集 / 設定 / 削除 / 非表示 / 表示に戻す / 閉じる / 戻る / 推移 /
           セット / 回数 / 秒数 / 重量 / 距離 / 部位 / 期間 / すべて
<面>.*     その面にしか出てこないもの
```

**同じ意味なら同じキーを使う。**面ごとに分けるのは、**語が同じでも意味が違うとき**だけ
（設定タブの「設定」＝場所、種目カードの「設定」＝その種目の性質）。
分けるときはキーに理由が出るようにする（`nav.settings` と `exercise.settings`）。

### 2.3 重複はテストで落とす

規約だけでは、書くたびに増える。**`ja.ts` に同じ値が 2 つあったらテストを落とす。**

```
同じ日本語が別のキーに入っている → どちらかは common に寄せられる
```

意味が違って同じ語になる場合（上の「設定」）は、**例外表に書いて通す。**
書けば「なぜ 2 つあるか」がその場に残る。数が増えたら、それは分け方のほうが
間違っている合図になる。

### 2.4 読み上げの名前も組み立てない

`${name}を編集` のような文が 20 か所以上ある。**これも 1 つのキー**にする
（`a11y.editOf` = `{name}を編集`）。ばらばらに書くと、英語で
`Edit {name}` に直すときに 20 か所を回ることになる。

## 3. 言語の決め方

`Settings.locale: 'system' | 'ja' | 'en'`。**テーマ（`ThemePref`）と同じ形。**

- `system` は `navigator.language` を見て、`ja` で始まれば日本語、ほかは英語
- 設定 > 一般 > 表示 に、テーマの隣として置く
- 記録（`AppData`）に入るので、**書き出した JSON を別の端末で読めば言語も移る**

配り方は `WeightUnitProvider` と同じ。出す場所が画面中に散っていて、
末端まで props で通すと関係のない部品にも引数が生える。

---

## 4. 種目名

**カタログ由来の名前は、記録に写ったあとも訳せるようにする。**

`fromCatalog` が `Exercise.name` へ名前を写すので、いま追加済みの種目は
日本語の名前をデータとして持っている。訳語に切り替えても、そのままでは日本語が残る。

```
表示する名前 =
  本人が改名していれば         → その名前（自作種目も同じ）
  カタログ由来で改名していなければ → いまの言語の名前
```

改名したかどうかは、**保存されている名前がその言語のカタログ名と一致するか**で見る。
判定を別のフラグで持たない——持つと、改名を取り消したときに古い印が残る。

- `exerciseCatalog.ts` の `name` は日本語のまま（基準）
- `catalogNames.en.ts` に **ID → 英名**の表を置く。**この表のキーがそのまま `CatalogId`**
- 検索（`exerciseSearch`）は**両方の言語で当てる**（`otherLocaleNames`）。英語で使っていても
  「ベンチ」で引けるほうが、切り替えた直後に困らない

### 4.1 「型で落ちる」をどこまでやったか

当初は `Record<CatalogId, string>` にして 143 件の抜けを型で落とす、と書いた。
そのためには `CATALOG` の `id` がリテラル型でなければならず、`as const` を付けると
**143 個のオブジェクト型の union** になり、`entry.implements` のような
「一部の行にしかない項目」がどこからも読めなくなる（既存の参照が全部壊れる）。

そこで**表のほうを ID の出どころにした。**`CatalogId = keyof typeof CATALOG_NAMES_EN`。

| | 落ち方 |
| --- | --- |
| 表に無い ID を書く | **型で落ちる**（`CatalogId` に無い） |
| カタログに種目を足して英名を忘れた | **テストで落ちる**（`i18n.test.ts`・両方向） |

`NOT_TRANSLATED` と同じ「2 方向のリスト」に落ち着いた。足りなくても、余っても落ちる。

### 4.2 言語は `t` が持ち歩く

種目名は辞書に無いので、引くのに**言語そのもの**が要る。
`t` を渡している場所すべてに `locale` をもう 1 本足すと引数が倍になるので、
`T` を「呼べて、`locale` を持つもの」にした（`makeT(locale)`）。
文言を引く相手と言語は必ず同じものなので、分けて持つ理由がない。

## 5. バッジ

`badges.ts` は `name` と `detail` を直書きしている（60 種・説明 63 文）。
ここを `nameKey` / `detailKey` に替えて、判定の値（閾値・条件）はそのまま置く。

**判定は訳さない。**「7 日すべて記録できた週」の数え方は言語で変わらない。

## 6. 日付・数

| | 方針 |
| --- | --- |
| 月日（`9/23`） | `Intl.DateTimeFormat(locale, { month:'numeric', day:'numeric' })` |
| 曜日（`(火)`） | `Intl.DateTimeFormat(locale, { weekday:'short' })`。`WEEKDAY_JA` は置き換える |
| 年月日 | `Intl.DateTimeFormat(locale, { dateStyle:'long' })` |
| 相対（`12日後`） | `Intl.RelativeTimeFormat` |
| 桁区切り | `toLocaleString(locale)`（`fmtVolume` が既に `toLocaleString`） |
| 小数点 | `toFixed` のまま。**区切り文字は訳さない**——入力欄に打つ値と、読む値をずらさない |
| 重量 | `kg` / `lb` は既存の仕組みのまま（言語とは別の設定） |

`lib/date.ts` は**純関数のまま**にして、locale を引数で受ける（既定は `'ja'`）。
グローバルな「いまの言語」を lib が読みに行くと、テストが順番に依存する。

## 7. テスト

- 既定を `'ja'` に固定する。**既存の 576 件はそのまま通る**
- 足すのは 4 つ
  - `en` に抜けが無い（型で落ちるが、辞書の件数もテストで見る）
  - **`ja.ts` に同じ値が 2 つ無い**（例外表に書いたものを除く。§2.3）
  - 改名した種目は言語を変えても名前が変わらない
  - 日付が言語で切り替わる

## 8. Phase

| | 内容 | 規模 |
| --- | --- | --- |
| 1 | 仕組み（辞書・`useT`・`Settings.locale`・設定の欄）＋ 画面の文言 | 大（約 90 か所 ＋ 地の文） |
| 2 | 種目カタログ 143 件 | 中（訳語の量） |
| 3 | バッジ 60 種 ＋ 説明 63 文 | 中 |
| 4 | 日付・相対表現 | 小 |

**1 は画面ごとに切る。**一度に全部剥がすと、通らなくなったときにどこが原因か分からない。
記録 → ホーム → 目標 → 設定 → トレーニングの順で、面ごとに検証を通す。

## 9. 採らないもの

| 採らない | 理由 |
| --- | --- |
| ロケールごとの週の始まり | 保存と集計の単位。過去の数字が全部変わる（§1.1） |
| 翻訳ライブラリ | ランタイムの依存を増やさない（§1.2） |
| コメント・設計メモの英訳 | 読むのは作者。理由の密度が落ちる（§1.3） |
| 自動翻訳での訳語生成 | 種目名は**器具と動作の名前**で、直訳すると通じない（ダンベルフライ → Dumbbell Fly） |
| 小数点・桁区切りの全面ロケール化 | 打つ値と読む値がずれる（§6） |

## 10. 抜け漏れを塞ぐ仕組み

**規約は守られない。**書く量が多いほど、書き忘れも書き足しも起きる。
落ちるようにしておく。落ち方は 2 通りで、**型で落ちるものは型に任せる**。

### 10.1 型で落ちるもの（書いた瞬間に赤くなる）

| 仕掛け | 何を防ぐ |
| --- | --- |
| `en: Record<MessageKey, string>` | 英語の訳し忘れ。`ja` に足して `en` に足さないとビルドが通らない |
| `CatalogId = keyof typeof CATALOG_NAMES_EN` | 表に無い種目 ID を書けない（カタログとの突き合わせは §4.1 のとおりテスト） |
| バッジは `nameKey: MessageKey` を持つ | キーの打ち間違い |
| `t` の引数は `MessageKey` | 無いキーを書けない |

### 10.2 テストで落ちるもの

`src/lib/i18n/i18n.test.ts` がソースを読んで突き合わせる。
`verify` の `vitest` に乗るので、**報告・コミット・デプロイの前に必ず通る。**

| 見るもの | 落ちる条件 |
| --- | --- |
| **重複（日本語）** | `ja` に同じ値が 2 つ（例外表にあるものを除く） |
| **重複（英語）** | `en` に同じ値が 2 つ。**日本語だけ見ていて 17 組すり抜けた**（§10.6） |
| **穴の食い違い** | `{n}` が片方の辞書にしかない（差し込んだ値が黙って消える） |
| **英語に日本語** | 訳し忘れ。キーはあるので型では見えない |
| **死んだキー** | 辞書にあるのに、どこからも `t('…')` されていない |
| **動的なキー** | `t(` の次が引用符でない（`t(cond ? a : b)` を禁じる。静的に追えなくなる） |
| **断片の継ぎ足し** | 値が空白で始まる／終わる（`直近 ` ＋ 値 と並べた跡） |
| **`<b>` での分割** | `{t('前')}<b>{t('語')}</b>{t('後')}`（§10.6） |
| **句点** | 文として終わるのに `。` が無い |
| **例外表の腐り** | 例外に挙げた語が、もう重複していない（消し忘れ） |
| **べた書き** | 画面のコードに日本語が残っている（§10.3） |
| **カタログの英名** | `CATALOG` と `catalogNames.en.ts` が食い違う（両方向） |

### 10.3 べた書きの検出 — **リストは減る一方にする**

いちばん効くのはこれ。`src/**/*.tsx` の

- JSX の地の文
- `aria-label` / `label` / `placeholder` / `title` の文字列

に日本語が残っていたら落とす。コメント・`docs/`・`ja.ts`・テストは見ない。

剥がしている途中は**未移行のファイル名を配列で持っていた**（`NOT_YET`）。
剥がし終わったので配列ごと消し、残ったのは**訳さないと決めた面**だけになった。

```ts
/** 剥がさないと決めた面。**理由を書く**——書けないものは剥がす */
const NOT_TRANSLATED: Record<string, string> = {
  'src/lib/exerciseCatalog.ts': '種目名の日本語はここが基準（§4）',
  'src/lib/seed.ts': 'デモの初期データ。作成者の記録そのもので、画面の文言ではない',
  'src/lib/perf.bench.ts': '開発者しか走らせない計測の見出し（§1.3）',
};
```

- リストに無いファイルに日本語が残っていたら**落ちる**
- リストにあるファイルから日本語が消えたら**落ちる**（理由が要らなくなったのに残っている）

**増やす向きには何も言わない。**言えないが、差分に追記が出ればレビューで必ず目に入るし、
理由の欄が空では書けない。

### 10.6 あとから足した検査 — **片側しか見ていなかった**

最初の検査は**日本語しか見ていなかった。**そのため、日本語では分かれているのに
英語で同じ語に潰れているものが 17 組あり、素通りしていた。

```
体重の変化 / 体重変化      → どちらも Weight change
種目を追加 / 種目を足す    → どちらも Add an exercise
```

同じ形の見落としがもう 1 つあった。**文を JSX で継ぎ足す**書き方は、
`t()` の中を見ても分からない。

```tsx
{t('checks.datesOnlyPre')}<b>{t('checks.datesOnly')}</b>{t('checks.datesOnlyPost')}
```

日本語では通るが、**英語では順が変わる**ので、割った場所をすべて直して回ることになる。
`{strong}` の穴にして `Strong` が埋める形に直し、同じ割り方が戻らないよう検査を足した。
値を空白で継ぎ足す形（`直近 ` ＋ 数値）も同じ穴で、こちらは**前後の空白**で検出する。

**教訓は「検査は書いた側の想像の範囲しか見ない」。**だから、見落としを 1 つ見つけたら
直すだけで終わらせず、**その形の見落としを落とす検査**を足す。

### 10.4 実行時の保険

辞書に無いキーを引いたら、**キーの文字列をそのまま返す**。
画面が空白になるより、`training.card.edit` と出ているほうが原因に辿り着ける。
開発ビルドでは併せて `console.warn` する（本番では黙る。利用者に出す情報ではない）。

### 10.5 順番

**この仕組みを先に入れる。**文言を剥がしてから検査を足すと、
剥がし終わるまで何も守られない。`NOT_YET` に全ファイルを入れた状態から始めて、
面を 1 つ剥がすごとに 1 行消す。**残りの行数がそのまま進捗になる。**
