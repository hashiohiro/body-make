# 波及を見せる 設計メモ

対象は 2 つ。**打鍵点の波及行**・**入力ダイアログの帯**。
（3 つ目の**週の読み取り**は取り下げた。§3）
別々の機能に見えるが、受けている問題は 1 つなので 1 本にまとめる。

---

## 1. 背骨

> **記録はすでに 8 つの面を動かしている。動いた場所に居なくても分かるようにする。**

1 セット打ったときに、実際に動くもの:

| 動くもの | どこに出るか | 打鍵点から |
| --- | --- | --- |
| その日の合計・前回比 | `ExerciseTotals`（カードと入力ダイアログの両方） | **見える** |
| 通算の最高（挙上量・記録した重量） | 同上 | **見える** |
| 週の部位別セット数 | ホーム `GroupSetsHeatmap` | タブ移動 |
| 部位の空き（回復） | 記録画面の帯 `TrainingAside` | 帯を開く |
| 部位目標の進捗 | 目標タブ `TrainingGoalBoard` | タブ移動 |
| 種目の目標の進捗 | 同上 | タブ移動 |
| 推移・推定1RM | ホーム > 推移 | 2 階層 |
| 継続バッジ・連続記録 | ホーム | タブ移動 |

**複利はもう実装されている。見えていないだけ。**
打った瞬間に見えるのは 8 つのうち 2 つで、残り 6 つは別のタブ、しかも切り替えの向こう側にある。

### 1.1 何を作らないか

**新しい導出を 1 つも作らない。**
`training.ts` / `check.ts` / `weekly.ts` に全部ある値を、打鍵した場所へ戻すだけ。
計算を足すと「計算の定義」表に行が増え、説明責任がそのぶん増える。ここでは増やさない。

### 1.2 表現の規則

`design-training.md` §1.2（褒めない）をそのまま引き継ぐ。

- 出すのは **数値と符号** だけ。矢印がすでに向きを持っている
- 「更新！」「あと少し」「いい調子」は書かない
- トースト・効果音・アニメーションを足さない。**行が出るだけ**

### 1.3 出す量の規則

**跨いだものだけを出す。変化がなければ 1 行も出ない。**

毎回 4 行出るものは、3 日で読み飛ばされる。
`design-checks.md` §3.3 と同じ失敗（抑制できない警告は、警告そのものが読まれなくなる）。
既存の流儀——`押せないものをボタンの形で出さない` / `入らない道を書かない`——の系として書く。

**例外が 1 つある。**部位の今週のセット数だけは、跨いでいなくても常に出す（§2.1）。
その一打が必ず動かすものが 1 つだけあり、部位目標を立てていない人にとっては
**これが唯一の「外に及んだ」情報**になるため。
ブロックが出たり消えたりしなくなる効果もある。

## 2. 打鍵点の波及行

### 2.1 出す条件

| | 条件 | 出どころ |
| --- | --- | --- |
| 部位の今週のセット数 | **常に出す**（目標があれば添える） | `buildWeeklySets` × `GroupGoals` |
| 部位の空き | 変わったときだけ | `requiredDays` / `groupReadiness` |
| 種目の目標 | 到達したときだけ | `exerciseGoals` |
| 通算最高 | **行を足さない**（§2.4） | `personalBest` |

### 2.2 「跨いだ」の定義

**打つ前と後の差ではない。**

> **その日のその種目の記録を「含まない場合」と「含む場合」の差。**

打鍵のタイミングに依存しない**純粋な導出**になる。閉じて開き直しても、
リロードしても同じ行が出る。`保存するのは生データだけで、計算した値は保存しない`
と同じ性格で、覚えておく状態が 1 つも増えない。

### 2.3 書式 — ラベル + 値の 2 列

```
胸 今週    8 → 11 セット（目標 10 に到達）
胸の次     9/25（11 セット → 2 日空け）
目標       62.5 kg に到達
```

ラベルの列がそろうので、行が増えても**左端をなぞるだけ**で読める。
上限 3 行。3 つ並ぶのは滅多にないが、並んだときの順は
**部位のセット数 → 部位の空き → 種目の目標**。外へ及んだ順に置く。

数値と符号だけ（§1.2）。「更新」「達成」は書かない——`→` が向きを持っている。
「到達」は線を跨いだという事実で、評価語ではないので使う。

### 2.4 通算最高は行を足さず、いまある行を書き換える

`ExerciseTotals` はすでに `最高重量 60.0 kg` を出している（`bestWeight` は**その日より前**の最高）。
波及行に `最高重量 60.0 → 62.5 kg` を足すと、**すぐ上の行と同じことを 2 回言う**。

その日が超えたときは、**その行自体**を `最高重量 60.0 → 62.5 kg` にする。行は増えない。
`残り（あと N kg）は出さない` は維持する——出すのは跨いだ事実だけで、距離ではない。

### 2.5 置き場所 — 入力ダイアログだけ。カードには出さない

`ExerciseCard` と `TrainingView` の両方に、同じ理由が書いてある。

> 並べたときにカードの高さがそろうので、いま打つ種目を探しやすい
> 1 種目に集中して打てるようにするのと、**カードの高さをそろえるため**

波及行は 0〜3 行で伸び縮みするので、カードに置くと**この理由を自分で壊す**。
カードは `要約と入口だけを持つ` と決めた面でもある。

打鍵点はそもそもダイアログなので、目的は損なわれない。
置き場所は `ExerciseTotals` の直下——**セットの行 → 合計 → 最高 → 波及**と、
内から外へ広がる順に並ぶ。

### 2.6 有酸素

部位を持たない（`有酸素は部位ではない`）ので、部位のセット数・部位の空きは出ない。
代わりに **`今週の有酸素  3 回 / 92 分`** を常に出す。
目標画面が部位と別に持っている「有酸素」の行と同じ軸で、**部位には入れない**。

「部位に入りません」とは書かない（入らない道を書かない）。

## 3. 週の読み取り（撤回）

**取り下げた。**実装まで進めたうえで、利用者の判断で不要とした。

ホームの先頭に、体組成の週次の差（体重・除脂肪・体脂肪量）とトレの週次（日数・セット数・部位別）を
同じ週の行に並べるカードだった。期間チップ（4 / 8 / 12 週 / 全期間）を持ち、
締まった週だけを並べ、切り替えに属さない唯一の面として置く設計。

コードは残していない。番号は §4 以降を動かさないために空けてある
（`TrainingView` のコメントが §2・§4 を指している）。

## 4. 入力ダイアログの帯

### 4.1 問題

1 セット打つまでの往復:

```
保存 → ダイアログを閉じる → スクロール → 次のカードを探す → 編集 → また開く
```

5 種目で 5 往復。セット間 90 秒、汗、片手。

### 4.2 出すもの — `ChipGroup`（既定）をそのまま使う

入力ダイアログの上端に、**その日に置いてある種目**を 1 行で。

```
(ベンチプレス)(インクラインベンチプレス)(ダンベルフ →
```

新しい部品も CSS も要らない。既定の `ChipGroup` が要件を全部持っている。

| 要る性質 | 持っているもの |
| --- | --- |
| 名前を省略しない | `.chip { white-space: nowrap }` |
| 高さが種目数で変わらない | `.chipRow` は 1 行（`tight` を**付けない**） |
| いま開いている種目が分かる | `aria-pressed` の選択状態 |
| 押せることが形で分かる | `選択肢から 1 つ選ぶ` ための部品そのもの |

- 並びは `dayEntries` の順（やった順）。**こちらは何も決めない**
- どれでも押せる。打ち終わった種目に戻るのも 1 タップ
- 押さなかった種目に印は残らない

**`tight`（折り返し）は使わない。**折り返すと種目数で帯の高さが変わり、
入力欄の縦位置が日替わりになる。`tight` が折り返しを選んでいるのは
一覧に重ねる絞り込みの話で、こちらは入力欄の上に固定で載る帯。

### 4.3 なぜモードにしないか（セッションモードの撤回）

順序を持った面は **計画型**（§11-3）。`3/5` という現在地は、
その日の順序を先に決めていないと出せない。順序を持った瞬間、
飛ばした種目は「やらなかった種目」になり、撤回したはずの未達が別の形で戻る。

**機器が埋まっていたから別の種目をやった、は未達ではなくその日の実績。**

帯はモードではない。いまのダイアログから **出口のコストを抜いただけ**で、
できることは 1 つも減っていない。

### 4.4 受ける 3 つの場面

| 場面 | 帯での受け方 |
| --- | --- |
| 機器が埋まっていたので別の種目をやる | `＋` が帯にある。閉じずに足して、そのまま打つ |
| さっきの結果を間違えていたので直す | 打ち終わった種目を押す。1 タップで戻る |
| 予定していた種目をやらなかった | 押さなければいい。印も残らない |

### 4.5 `＋` から足した直後は開かない（現状維持）

`TrainingView.toggle` の判断——`ピッカーが開いたままなので、面が重なる`——はそのまま。
足した種目は帯に現れるので、1 タップで届く。

### 4.6 過去の日でも同じ

帯はその日の `dayEntries` から作るので、日付ナビやカレンダーで遡った日でも同じに出る。
訂正はここで完結する。

### 4.7 種目が多い日 — 画面外に出る枠をどう受けるか

1 行に収めるので、6 種目の日には画面外へ出る枠がある。
`.tight` のコメントが折り返しを選んだ理由（`隠れたチップを探しに行かせない`）は、
ここでは 2 つで受ける。

- **並びが固定**（`dayEntries` = やった順）。位置で覚えられる
- **開いた種目のチップまで自動で寄せる**
  （`scrollIntoView({ inline: 'center', block: 'nearest' })`）。
  いまどこに居るかは必ず見えるので、迷子にならない
- **まだ続く側の端を薄くして、`›` を出す**（§4.7.1）

スクロールバーは `hide-scrollbar` で消える（`.chipRow` が既に持っている）。

### 4.7.1 続きがあることを、端の印で出す

端でちょうど切れた行は、そこが終わりに見える。**流せると分からなければ、
隠れたチップは無いのと同じ**なので、帯を置いた意味がなくなる。

| | |
| --- | --- |
| 出すもの | 続きがある側にだけ `‹` / `›`。流し終わった側からは消える |
| 描き方 | **字ではなく図（インライン SVG）。**`‹` `›` の字は文字の並びに混ぜて使うものなので、フォントごとに上下の位置が違う。箱を中央に寄せても字が箱の中央に無く、寄って見えない。色は `currentColor` で受けるので、`--caret` と違って配色ごとの定義が要らない |
| 上下の合わせ先 | **行ではなくチップ**（`height: var(--tap-sub)`）。行は下に 2px の余白を持っているので、`bottom: 0` で伸ばすとそのぶん下へずれる |
| 端の薄め方 | **マスクで抜く**（`mask-image`）。背景色を重ねない——この行はダイアログの中にもカードの上にも出るので、地の色を知っていることを前提にできない |
| 押せるか | **押せない**（`pointer-events: none`）。押して動かせるようにすると、端まで行くのに何度も押すことになる。ここが答えるのは「まだ続く」までで、動かすのは指 |
| 読み上げ | 出さない（`aria-hidden`）。選択肢そのものは行が持っている |

測り直すのは **流したとき**と**幅が変わったとき**（横向き・キーボード）。
`scrollLeft` は端でぴったり 0／最大値にならないことがあるので、**1px の遊び**を持たせる
（持たせないと、終わりまで流したのに `›` が残る）。

### 4.8 誤操作を塞ぐ

打っている最中の面に横スクロールを置くので、**払ったスワイプが外へ抜けないようにする。**

| | すること | いまどうなっているか |
| --- | --- | --- |
| 端まで払ったときに外へ連鎖する | 帯に `overscroll-behavior-x: contain` | `global.scss` は **`-y: none` しか持っていない**。横は塞いでいないので、ここで自分で持つ |
| 縦スクロールを奪う | 帯の外の縦は今までどおり流す | `Modal` の body が `overscroll-behavior: contain` を持っている。チャートが `touch-action: pan-y` で同じことをしている前例がある |
| 押して動かそうとする | **右端でチップを切る。**次の枠の一部を覗かせて、流せることを形で見せる | `.chipRow` は端で切れるだけなので、覗かせるぶんの `padding-inline` を足す |
| 的が小さい | そのまま。`.chip` は `min-height: var(--tap-sub)` を持っている | 変更なし |

ブラウザの「戻る」ジェスチャと取り違えるのがいちばん怖い経路なので、
1 つ目（`overscroll-behavior-x`）は**帯を置くのと同時に入れる。**あとから足さない。

## 5. 現在地の置き換え

帯は順序を持たないので `3/5` が出せない。その穴は波及行が埋める。

| | 出すもの | 何に対する現在地か |
| --- | --- | --- |
| `3/5` | 計画のどこまで来たか | **計画**（持たない） |
| `胸 今週 8 → 11（目標 10）` | いま何が積み上がったか | **実績** |

計画を持たずに現在地だけが出るので、未達が生まれない。
**§2 と §4 は片方がもう片方の穴を塞ぐ組み合わせで、別々に入れると半分になる。**

## 7. 採らないもの

| 採らない | 理由 |
| --- | --- |
| 進捗カウンタ（`3/5`）・セッションモード | 順序を持つと計画型に戻る（§11-3） |
| トースト・効果音・祝福のアニメーション | 演出（§1.2）。出るのは行だけ |
| 波及行を毎回出す | 読み飛ばされる（`design-checks.md` §3.3 と同じ失敗） |
| 波及行に「部位に入りません」等の注記 | 入らない道を書かない |
| 帯に未入力の印・やり残しの数 | 未達の表示そのもの |

## 10. 帯に `＋` を置かない

チップ行は「選択肢から 1 つ選ぶ」部品なので、`＋` は選択肢ではない。混ぜると
`ChipGroup` の契約が壊れる。それ以上に、`＋` が開く `ExercisePicker` は検索と
カタログを持つ面で、**ダイアログの上に重なる**（`TrainingView` が避けている状態）。

**置いてある種目を行き来するのは毎セット起きるが、種目を足すのはその日 1 回あるかどうか。**
しかも検索の要る、形の違う操作になる。稀で形の違う操作のために、毎回使う帯の性格を変えない。

機器が埋まっていた日には 1 往復が残る。**それは引き受ける。**

| 検討した案 | 採らない理由 |
| --- | --- |
| `＋` を置き、ピッカーを重ねる | 面が重なる。既存の判断と逆 |
| `＋` を置き、押すとダイアログが閉じてピッカーが開く | 打ちかけの面が一度消える。閉じてから足すのと結局同じ手数 |
