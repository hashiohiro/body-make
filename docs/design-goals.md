# 目標画面 設計メモ

グラフタブを目標タブに差し替え、いまある項目を既存の UI へ繋ぎ変えるための設計。
あわせて「入力が多くて初見になじみにくい」を、機能を落とさずに削るところまでを扱う。

[design-training.md](design-training.md) §15「決定済み」のうち、この改修で覆すものは §8 に差分としてまとめてある。
検討したが採らなかった案は §9 に理由つきで残す（蒸し返さないため）。

---

## 1. 背骨

> **見る場所と、決める場所を一致させる。
> 分析はタブではなく、その数字の続きに置く。**

改修前のアプリは「目標まであと 3.2kg」を**ホーム**に出し、その 3.2kg を決め直す場所を
**設定 > 体組成 > 目標**に置いていた。2 タブ離れている。
`GoalMeter` が `onOpenSettings` を持って設定へ飛ばしていたのは、その距離を埋めるための応急処置で、
距離のほうを無くせば要らなくなる。

同じことがグラフにも起きていた。ホームの `Hero` にはスパークラインがあり、`StatTiles` には開始比がある。
その続きを見るには、タブを移動し、期間を選び直す必要があった。
**推移は独立した機能ではなく、いま見ている数字の続きである。**

### 1.1 目標は「設定」ではない

設定に置くものは「滅多に変えない定義」で、目標体重・目標日・週のセット数・種目の目標は
**進捗を見ながら何度も変わる**。頻度が違うものを同じ階層に置いたのが、往復の原因になっていた。

役割をこう定義し直す。

| 画面 | 役割 |
| --- | --- |
| ホーム | いまどうなっているか（状態） |
| **目標** | **どこへ向かうか（目標と、それに対する進捗）** |
| 記録 | 入力 |
| **設定** | **定義**（種目そのもの・表示・データ） |

### 1.2 グラフの降格ではない

タブから外すが、**グラフの中身は 1 つも減らさない。**
期間チップ、指標チップ、部位の絞り込み、種目の詳細ダイアログ、カロリー収支の集計期間、表、すべて残す。
移すのは置き場所だけ。

### 1.3 変えないもの

§1.1「指示をしない」・§1.2「褒めない」・§1.3「意識して入れた値だけを指標にする」は変えない。
目標画面は**目標値を置く場所**であって、目標を提案する場所ではない。
既定値の発明もしない（「標準 12」のような目安は、押して初めて入る**選択肢**であって初期値ではない）。

## 2. タブと切り替えの関係

```
ホーム / グラフ / 記録 / 設定          いま
                   ↓
ホーム / 目標  / 記録 / 設定          変更後

ヘッダ  [ 体組成 | トレーニング ]      ← 既存。設定以外のすべての画面に効く
```

**タブは 4 つのまま**（§7.1 の決定は維持）。増やさず、差し替える。

体組成／トレーニングの切り替え（`Domain`）はすでにヘッダにあり、ホーム・記録・グラフを横断している。
**目標タブと推移画面も、この切り替えに従わせる。**
目標タブだけ「体組成の目標もトレーニングの目標も 1 画面に並ぶ」形にすると、
同じアプリの中で切り替えの意味が場所によって変わる。

| 切り替え | ホーム | 目標 | 記録 | 推移 |
| --- | --- | --- | --- | --- |
| 体組成 | 現在地・実績 | 目標体重と到達予測 | 朝夕の入力 | 体重・体脂肪率・週平均・カロリー収支 |
| トレーニング | 今週・部位別の配分 | 週のセット数と種目の目標 | セットの入力 | 種目別の推移 |

## 3. グラフの行き先

### 3.1 下位画面 1 つ。中身は切り替えに従う

`ChartsView` はすでに `domain` を受け取って中身を出し分けている。
**画面を 2 つに割る必要はなく、下位画面 1 つ（`#home/trend`）に移すだけでいい。**

- `#home/trend` — 見出しは切り替えに従って「体組成の推移」「トレーニングの推移」
- 期間チップはこの画面が持つ（画面に効くフィルタが画面の中にある形）

### 3.2 入口はホームの最後

ホームは「現在地 → 実績」の順に並んでいる。その続きとして、それぞれの側の最後に 1 行置く。

```
ホーム（体組成）                     ホーム（トレーニング）
┌ 68.4 kg  −3.2  ∿∿∿ ┐              ┌ 今週 3日 ┐┌ 通算 42回 ┐
│ 体脂肪率 / 体脂肪量 / 連続 │              │ 部位別の配分（12週 × 6部位） │
├──────────────┤              ├────────────────┤
│ 体重・体脂肪率の推移   › │              │ 種目別の推移          › │
└──────────────┘              └────────────────┘
```

カード自体をボタンにする（`ui.card` ＋ `ui.linkRow`）。新しい見た目の語彙を足さない。

種目の目標の行からも `#home/trend/<種目ID>` で入れる。
着いた先で**その種目の詳細ダイアログが開いた状態**にする（`TrainingCharts` の `initialOpenId`）。
目標 → 推移の導線がここで繋がる。

### 3.3 URL と互換

`App.tsx` はすでに `#tab/section` の下位画面と「遷移元へ戻る」を持っている。
これは設定専用の仕組みではないので、**セクション名の解決だけ一般化すれば受け皿になる。**

- `settingsSectionTitle()` を、タブ横断の登録表（`SECTIONS`）に置き換える
- 種目 ID を載せるため、`Route` に `param` を足す（`#home/trend/ex_bench`）
- **`#charts` は `#home/trend` へ `replaceState` で寄せる。**
  PWA のホーム画面から復帰したときと、ブックマークを開いたときに壊れないようにする

## 4. 目標画面

### 4.1 体組成の側

```
目標                      [ 体組成 | トレーニング ]
┌────────────────────────────────
│ 目標まで あと 3.2 kg                        64%
│ ▓▓▓▓▓▓▓▓▓░░░░░
│ 開始 78.0kg                           目標 72.0kg
│
│ 現在のペース（直近28日）               −0.35 kg/週
│ このペースでの到達         2026-10-02（39日後）
│ 10-31 までに必要なペース               −0.48 kg/週
│ 体脂肪率                     21.3% → 目標 18.0%
│ BMI（身長 172cm）                          22.4
│ [ 目標を変更 ]
└
```

`[目標を変更]` で、目標体重・目標体脂肪率・目標日・身長がカードの中に開く。設定へは飛ばさない。

**`stats.bmi` は計算されているのに、どこにも表示されていなかった**（`derive.ts` で算出、参照ゼロ）。
つまり身長は「BMI を計算するためだけの設定で、その BMI が出ない」状態だった。
身長そのものは目標ではないが、**目標体重と BMI は同じ話題**なので同じ面に置く。
これで身長を聞く理由が画面の中で完結する。

### 4.2 トレーニングの側

```
┌ 週の部位別セット数の目標 ──────────
│ [少なめ 8][標準 12][多め 16][決めない]
│ 胸    [ 12 ]   背中  [ 12 ]  …
└
┌ 種目の目標 ────────────────── 3件
│ 直近28日  自己最高 2種目  4週以上動いていない 1種目
│ 胸    2/3 到達  ▓▓▓▓▓▓▓░░  71%
│  └ ベンチプレス   92.5 kg   目標 100 kg
│     [ 推移を見る ] [ 変更 ]
│ [ ＋ 種目に目標を決める ]
└
```

**実績はここに出さない。** 週の部位別の実績はホームの「部位別の配分」（ヒートマップ）が持っている。
同じ数字を 2 か所で見せない（`TrainingSummary` から「今週の部位別セット数」を外したときの決定と同じ）。

### 4.3 目標の決め方

```
┌ ベンチプレス ─────────────────
│ [   重量   |   回数   ]        ← 2 択。開いて選ばせない
│ [        100        ] kg      ← 決める値なので、ここがいちばん大きい
│ いま 92.5 kg ・ 過去最大 95.0 kg
│ [ 目標を外す ]
│ 判定は、その日いちばん重かった記録した重量で行います。
└
```

**種類はドロップダウンにしない。** 2 択を開く → 選ぶ → 閉じるの 3 手にする理由がなく、
選んだ瞬間に単位（kg / 回 / 秒）が変わることが見えたほうが決めやすい。
ヘッダの体組成／トレーニングと同じセグメントを使う（見た目の語彙を増やさない）。

**「いま」と「過去最大」を添える。** 100kg を目標にするかは、いま何 kg 挙がっているかを
見ないと決められない。決める材料が同じ面に無いと、目標画面と推移画面を往復することになる。

**値は入れない。** 現在値を初期値として置くと、アプリが目標を発明することになる（§1.3）。
出すのは事実だけで、決めるのは人。

**単位は入力欄の横に出す。** placeholder に置くと、打ち始めた瞬間に消えて
「何の数字か」が分からなくなる。体組成の目標（kg / % / cm）と週のセット数も同じにそろえる。

### 4.4 移設表

| いまの置き場所 | 移設先 |
| --- | --- |
| `GoalMeter`（ホーム） | 目標（体組成） |
| 設定 > 体組成 > 目標（目標体重・体脂肪率・目標日） | 同カードの `[目標を変更]` |
| 設定 > 体組成 > 身長 | 同上（§4.1） |
| 設定 > トレーニング > 週の部位別セット数の目標 | 目標（トレーニング）＝ `WeekGoals` |
| `TrainingGoals`（ホーム） | 目標（トレーニング） |
| 設定 > 種目 > 各行 `[設定]` > 目標 | 目標（トレーニング）の各行から直接 |

ホームに残るもの — `Hero` / `StatTiles` / `TrainingSummary` / `GroupSetsHeatmap` /
`StreakStrip` / `BadgeGrid`。
**実績（ストリークとバッジ）は目標ではないのでホームに残す。**
「何日続いたか」は目標に対する進捗ではなく、起きた事実の記録で、性格が違う。

### 4.5 種目マスタの一覧は再掲しない

§7.5 の「同じ一覧を 2 回出さない」は守る。
目標画面に出るのは**目標を持つ種目だけ**の進捗リストであって、35 行のマスタではない。
目標を新しく決めるときだけ `[＋ 種目に目標を決める]` から選ぶ。

目標の入力そのものは `GoalEditor` に切り出し、行の `[変更]` と追加モーダルで共有する。
同じ入力を 2 つ持つと、片方だけ直る事故が起きる。

## 5. 設定は 2 画面になる

```
設定
  トレーニング   種目の追加・並び・詳細設定       ›
  一般          表示・データ・このアプリについて   ›
```

設定 > 体組成は中身がすべて目標画面へ移るのでカテゴリごと消える。
種目の各行の `[設定]` は**詳細設定を直接開く**ようになる（目標が抜けた 1 段ぶん浅くなる）。
その内側の「計算方法を変える」はそのまま残す。

## 6. 入力を軽くする

効く順に 5 つ。いずれも既存の思想（± ボタンを置かない / 空欄を並べない / 指示をしない）と衝突しない。

### 6.1 日付ナビをヘッダへ上げる

`QuickEntry` と `TrainingView` に `‹ [日付] › [今日]` の 4 部品が**同じものとして 2 回**書かれていた。
日付は記録タブ全体の状態（体組成とトレーニングで同じ日を見続ける）なので、**置き場所も 1 つが正しい。**
体組成／トレーニングの切り替えをヘッダに置いたのと同じ理由で、日付もヘッダに置く。

```
記録            ‹  2026-08-24  ›  [今日]
[ 体組成 | トレーニング ]
┌ 体組成 ────────────────
│ ☀️ 朝   体重 [ 68.4 ]   体脂肪率 [ 21.3 ]
│ 🌙 夜   体重 [      ]   体脂肪率 [      ]
│ この日の平均            68.4 kg / 21.3 %
└
```

入力カードから 4 部品が消えて、**カードには入力欄だけが残る。** 重複コードも 1 本になる。

- **カードの見出し（体組成 / トレーニング）は残す。** 記録一覧がどちらの側にもあるので、
  入力カードの見出しが「いまどちらを入れているか」の目印になる
- **「今日」ボタンは今日を見ているときは出さない。** 押しても何も起きないボタンを、
  いちばん狭い行に無効のまま置き続ける理由がない

### 6.2 記録タブの行き止まりを塞ぐ

**初見の人がいちばん詰まるのはここ。** 種目マスタの初期状態は空（§3 の決定）なので、
記録 > トレーニングを開くと出るのは

> 種目がありません。設定 > トレーニング から追加してください。

という**指示だけ**で、その場では何もできなかった。

→ 同じ場所に `[＋ マイ種目に追加]` を置き、設定と同じカタログを開く。
種目ピッカーの中にも `[＋ マイ種目を増やす]` を置く。
**入口を増やすだけで、管理の場所（設定タブ）は動かさない。**

カタログは `CatalogPicker` に切り出して、設定のマイ種目と共有する。

### 6.3 その日のメニューを 1 タップで複製

「前回の構成で始める」は種目カード単位なので、3 種目やる日は
「種目を追加 ×3 → 複製 ×3」で 6 タップかかる。

日単位の複製を、その日の操作カード（日付ナビが抜けたぶんの置き場所）に出す。

```
┌ トレーニング ───────────────────
│ 3/10 (火) の記録はまだありません。
│ [ 前回と同じ（3/7 胸・腕 3種目） ]
│ [ ＋ 種目を追加 ]
└
```

§7.2 の「前回のセット列を丸ごと複製する 1 タップが本命の動線」を、日の単位に引き上げただけ。
入るのは前回の実績のコピーで、値はすべて編集できる。予定でも指示でもない。
**その日にすでに何か入っているときは出さない**（`ExerciseCard` の複製と同じ作法）。黙って上書きしない。

種目を足す入口も、この先頭カードへ移す。カードが積み上がるほど、下にあると遠くなる。

### 6.4 自作種目は「名前・部位」だけで作れる

追加フォームは 4 つ聞いていた（名前 / 部位 / 負荷の数え方 / 回数の単位）。うち 2 つは専門語で、
カタログにない種目を 1 つ作ろうとした瞬間に出てくる。

→ **負荷の数え方と回数の単位を `[詳細設定]` の中へ移す**（既定 `standard` / `reps`）。
機能は詳細設定に残るので水準は落ちない。
すでにある「触らなければ既定値で作られます」の注記が、そのまま本当になる。

### 6.5 用語に 1 行を添える

「挙上量」「推定 1RM」「トップセット」は、注記のある場所とない場所がある。
`ui.note` の作法で、各画面の初出に 1 行だけ添えて統一する。
新しい UI 部品（ツールチップ・?アイコン）は足さない。

### 6.6 採らない

**朝／夜を時刻から自動で選ぶ。** 初見の入力欄を 4 → 2 に減らせるが、
§11-2 で自動タイムスタンプを撤回したのと同じ問題に入る。
朝に測った値を夜に入れることが普通にある以上、既定が当たらない日が必ず出る。
**4 欄が一度に見えていることのほうが、モードを 1 つ増やすより安い。**

## 8. 覆す決定（design-training.md §15 への差分）

| 覆す決定 | 変更後 | 理由 |
| --- | --- | --- |
| 画面の役割 = ホーム=状態 / グラフ=分析 / 記録=入力 / 設定=設定（§11-22） | グラフ → **目標**、設定 = **定義** | 分析は「その数字の続き」であってタブではない（§1） |
| 設定の構造 = 体組成 / トレーニング / 一般 の 3 画面（§7.5） | **トレーニング / 一般 の 2 画面** | 体組成の中身が目標画面へ移り、カテゴリが空になる |
| 種目の目標は種目マスタの行で編集（§7.5） | **目標画面で編集**。設定側は詳細設定のみ | 見る場所と決める場所を一致させる |
| ホームに `GoalMeter` / `TrainingGoals` を置く（§7.6） | **目標画面へ移す**。ホームは状態と実績 | 同上 |

**維持する決定** — タブは 4 つ（§7.1）/ 体組成とトレーニングを同じ軸に並べない（§5.2）/
種目をまたいだ合計を出さない（§7.3）/ ± ボタンを置かない（§7.2）/ 同じ一覧を 2 回出さない（§7.5）/
種目マスタの置き場所は設定（§7.5）/ 種目の目標は最大重量で判定（§6.5）。

**失うもの** — 推移への到達が 1 タップから 2 タップになる。
代わりに、数字とその推移が同じ導線に並び、ホームから目標の編集までが 2 タップで届く。

## 9. 採らないもの

| 採らない | 理由 |
| --- | --- |
| 推移を体組成用とトレーニング用の 2 画面に分ける | ヘッダの切り替えが同じことをしている。同じ役割の仕組みを 2 つ持たない |
| 目標画面で体組成とトレーニングを 1 画面に並べる | 切り替えの意味が画面ごとに変わる（§2） |
| 目標画面から設定へ飛ばす編集 | いまの往復がそのまま残る |
| 目標画面に種目マスタの一覧を再掲 | 同じ一覧が 2 か所に出る（§4.5） |
| 目標画面に週の実績を再掲 | ホームの部位別の配分と同じ数字になる（§4.2） |
| 初回起動のウィザード／チュートリアル | 空状態が道案内を兼ねる。専用画面は初回しか使われず、2 回目以降は死んだコードになる |
| 目標値の推奨・既定値の発明 | §1.3。基準をアプリが決めることになる |
| 目標の初期値に現在値を入れる | 同上。事実（いま・過去最大）を出すところまでにする（§4.3） |
| 記録画面の「この日 N種目」 | 入っている種目はカードとして並んでいる。数だけ添えても読むものが増える |
| 朝／夜の自動判定 | §6.6 |
| 目標の達成通知・お祝い | §1.2「褒めない」 |

## 10. 決定済み

| 項目 | 決定 |
| --- | --- |
| タブ構成 | ホーム / **目標** / 記録 / 設定。4 つのまま差し替える |
| 推移の置き場所 | ホームの下位画面 1 つ（`#home/trend`）。中身は切り替えに従う |
| 推移の機能 | **1 つも落とさない。** 期間・指標・部位の絞り込み・詳細ダイアログ・表すべて維持 |
| 推移の見出し | 「体組成の推移」「トレーニングの推移」を切り替えで出し分ける |
| `#charts` | `#home/trend` へ `replaceState` で寄せる |
| 目標画面 | 切り替えで出し分ける。体組成＝目標と予測 / トレーニング＝週のセット数と種目の目標 |
| 目標の編集 | **その画面の中で完結。** 設定へ飛ばさない |
| 身長と BMI | 目標画面（体組成）へ。BMI を初めて画面に出す |
| 週の実績 | 目標画面には出さない。ホームの部位別の配分が持つ |
| ストリークとバッジ | **ホームに残す。** 実績は目標ではない |
| 設定の構造 | トレーニング / 一般 の 2 画面 |
| 種目マスタの置き場所 | **設定のまま。** 記録タブからは入口だけ足す |
| 種目の目標の入力 | `GoalEditor` に切り出し、行と追加モーダルで共有 |
| 目標の種類 | セグメントで 1 タップ。ドロップダウンにしない（§4.3） |
| 目標を決める材料 | 「いま」と「過去最大」を添える。値は入れない（§4.3） |
| 単位の出し方 | 入力欄の横に置く。placeholder に置かない（§4.3） |
| 種目を追加のボタン | 幅いっぱい。隣にその日の種目数を添えない |
| カタログの追加 | `CatalogPicker` に切り出し、設定と記録タブで共有 |
| 日付ナビ | 記録タブのヘッダに 1 つ。カードからは外す |
| 入力カードの見出し | 残す（記録一覧と区別する目印になる） |
| 「今日」ボタン | 今日を見ているときは出さない |
| 日単位の複製 | 置く。その日が空のときだけ出す |
| 種目を足す入口 | その日の操作カード（先頭）へ |
| 自作種目の入口 | 名前と部位だけ。負荷の数え方と回数の単位は詳細設定へ |
| 計算 | **1 つも変えない。**`lib/` は触らない |
