# 目標ペースの可視化 設計メモ

目標タブ（体組成）に、**いまのペースと目標に要るペースの差**・**目標の体組成**・**その間の推定1RM**を
図で並べるための設計。実装前の合意事項。

元の案は「週次チェックイン」のモックアップ（カロリーの提案＋採用／様子見、遅れ・速すぎの判定、
目標体重の提案、筋力低下の警告）だった。既存仕様と突き合わせた結果、**図はそのまま使い、
判定と提案はすべて落とす**。落としたものと理由は §7 に残してある（蒸し返さないため）。

---

## 1. 背骨

> **差を図にする。差の読み方は言わない。**

`design-training.md` §1.1「指示をしない」、§1.2「褒めない」、`design-goals.md` §1.3
「目標画面は目標値を置く場所であって、目標を提案する場所ではない」は変えない。

この機能で新しく出す数字は、すべて**利用者が入れた値（記録・目標）からの算術**で、
アプリの側で決めた閾値や既定値を 1 つも持たない。

| | 出す（事実） | 出さない（判定・指示） |
| --- | --- | --- |
| ペース | 実績 +0.23 kg/週・必要 −0.44 kg/週・その差 | 「遅れ」「速すぎ」「順調」 |
| カロリー | 推定収支 +240 kcal/日・必要な収支 −456 kcal/日 | 「1日 150 kcal 減らしましょう」 |
| 目標 | 目標の除脂肪体重 63.0 kg・現在 62.9 kg | 「70 kg にしませんか」 |
| 推定1RM | 直近 28 日の推移と差 | 「ペースが速すぎるかも」 |

### 1.1 なぜ図にするのか

`GoalMeter` はすでに `pacePerWeek` と `requiredPerWeek` を**文字で 2 行**出している
（「ペース +0.23 kg/週」「12/31 までに必要なペース −0.44 kg/週」）。
事実としては足りているが、**2 つの符号が逆だということが一目で読めない**。
同じ 2 つの値を 1 本の軸に乗せれば、判定語を足さなくても差は見える。

### 1.2 行動側からの裏取り

`design-training.md` §1 が筋トレログを入れた目的は
「除脂肪体重を保てているかを行動側から裏取りする」ことだった。
体重が動いている期間の推定1RMを**同じ画面に並べる**のは、この目的にそのまま沿う。
並べるだけで、「落ちているなら減量が速すぎる」という因果は言わない。

## 2. 何を出すか

| # | 置き場所 | 出る条件 | 中身 |
| --- | --- | --- | --- |
| A | **目標のカード（`GoalMeter`）の中**（`PacePanel`） | 目標体重と記録がある（＝目標のカードが進捗を出している） | 1 本の軸に実績と必要ペースの 2 点、kcal/日への換算、直近 28 日＋目標日までの小さな推移図 |
| B | 目標の体組成（カード） | `targetWeight`・`targetBodyFat`・`currentLeanMass` がある | 現在と目標を積み上げ棒 2 本で並べる（除脂肪／脂肪） |
| C | 推定1RM（カード） | 目標体重があり、目標の種類が「重量」の種目が 1 つ以上ある（直近 28 日に記録が無ければ空の文を出す） | 種目ごとの直近 28 日のスパークラインと差 |

**目標体重が無ければ、どれも出さない**（`GoalMeter` の空状態が入口になる）。

### 2.0 A は目標のカードそのものに入れる（2026-09-27 に変更）

初めは A を独立したカードにして、実績と必要の両方が出るときだけ出していた。
これだと**記録が足りない・目標日が無いときにカードごと消え**、何を入れれば出るのかが読めなかった。
また「目標まで あと ○kg」のカードとペースのカードが縦に並び、同じ目標の話が 2 枚に割れていた。

→ A は目標のカードの中に置き、**枠は常に出す。**出ない側のタイルは値を「—」にして、
入れ方を 1 行添える（「直近28日に体重を4日以上記録すると出ます。」「目標日を決めると出ます。」）。
ゲージは出た点だけを描き、差は 2 点が揃ったときだけ描く。
目標のカードにあった「現在のペース」「必要なペース」「体脂肪率」の文字の行は消した
（ペースは A が、体脂肪率の目標は B が図で出す）。

### 2.1 C の種目は利用者が選んだもの

「ビッグ3」のような括りはこちらで発明しない（`design-goals.md` §1.3）。
**重量の目標を決めた種目**（`exercise.goal.type === 'weight'`）を対象にする。
重さを伸ばしたいと利用者が意思表示した種目なので、減量中に見たい種目と一致する。

## 4. 計算の定義

新しいファイル `src/lib/pace.ts` に**純関数だけ**を置く。画面は結果を描くだけにする。

### 4.1 ペース

```ts
export interface PaceGap {
  pace: number;          // kg/週
  required: number;      // kg/週
  kcalPace: number;      // pace × KCAL_PER_KG / 7
  kcalRequired: number;
}
export function paceGap(p: Projection): PaceGap  // 各値は出なければ null
```

`pace` か `required` が出なければ、その側だけ null にして返す（枠は出し続ける。§2.0）。
kcal は `computeEnergyBalance` と同じ換算で、**収支の推定であって摂取量の指示ではない**。
表示の語も「推定収支」「必要な収支」にし、「摂取」「目標カロリー」とは書かない。

### 4.2 ゲージの軸

軸の端は `min(pace, required, 0)` と `max(pace, required, 0)` に余白 20% を足したもの。
**0 を必ず含める**（増えているか減っているかは符号で読むので、0 の位置が要る）。
帯や色分けの区間は持たない（区間の幅がそのまま「適正」の発明になる。§7-3）。

### 4.3 目標の体組成

```ts
export interface TargetComposition {
  current: { lean: number; fat: number };
  target: { lean: number; fat: number };
  leanDelta: number;                    // target.lean − current.lean
  weightAtCurrentLean: number;          // current.lean / (1 − targetBodyFat/100)
}
export function targetComposition(settings: Settings, stats: Stats): TargetComposition | null
```

`weightAtCurrentLean` は「いまの除脂肪体重のまま目標体脂肪率になる体重」。
**算術の結果として 1 行出すだけ**で、目標欄に入れるボタンは付けない（§7-4）。

### 4.4 推定1RM

```ts
export interface StrengthTrack {
  exerciseId: string;
  points: { date: string; value: number }[];  // 直近 PACE_WINDOW 日の oneRm
  delta: number | null;                       // 最新 − 最初の 3 点の平均（2 点未満なら null）
}
export function strengthTracks(
  sessions: readonly SessionPoint[],
  exercises: readonly Exercise[],
  today: string,
): StrengthTrack[]
```

窓は `derive.ts` の `PACE_WINDOW`（28 日）を export して共有する。**ペースと同じ期間を見る**ため。
`oneRm` が出ない点（12 レップ超など）は飛ばす。

差の基準は**窓の最初の 3 点の平均**（最新点は含めない。点が 3 つ以下なら最新以外のすべて）。
1 点目だけを基準にすると、その日の調子が差に乗り続ける——`exerciseBaseline` が
「最初の 3 セッションの平均」を開始値にしているのと同じ理由。
（例：ベンチは 1 点目 70.5 を基準にすると +7.5、2 点目 86 なら −8.0 と、どこから数えるかで符号まで変わる。）

## 5. 画面

### 5.1 並び

```
目標タブ（体組成）
├ GoalMeter        あと ○kg・進捗バー → A ペース（PacePanel）→ 到達予測・BMI → 目標を変更
├ B 目標の体組成
└ C 推定1RM
```

### 5.2 色

**新しい色の割り当ては作らない。** 増減の数値は、ヒーローやタイルと同じく
`deltaTone()` → `TONE_CLASS` で塗る（除脂肪の差・推定1RM の差は `lowerIsBetter=false`、
除脂肪は `Hero` と同じ tolerance）。

ゲージの 2 点（実績・必要）は**増減ではなく位置**なので `deltaTone` を通さない。
系列色で描き分け、明度も変えて色覚に頼らず区別できるようにする。
ゲージの区間を good / bad で塗ることはしない（§7-3）。

### 5.3 推移グラフには足さない

目標日までの到達線は、**カード A の小さな図の中にだけ**描く。
体組成の推移グラフ（`BodyTrendCharts`）の x 範囲は「最初の記録〜今日」なので、
目標日まで伸ばすと過去が縮む。既存の `reference`（目標体重の水平線）はそのまま残す。

### 5.4 文言（`ja.ts` / `en.ts` に対で足す）

新しいキーは `pace.*`・`composition.*`・`strength.*`。
既にある語は**使い回す**（`i18n.test.ts` の「重複が無い」）：
「今日」は `common.today`、「除脂肪」は `table.lean`、「推定1RM」は `metric.oneRm`。

kcal の語は「推定収支」にし、「摂取」「目標カロリー」とは書かない。
強める位置は辞書が持つ（`Strong`）。`<b>` で割らない。

| # | 元の案 | 理由 |
| --- | --- | --- |
| 1 | 「−150 kcal/日」の提案と［採用］［様子見］ | 摂取量を指示することになる（§1.1）。採用の履歴を持つと計画型になり、「未達」の状態ができる |

| 6 | 週 1 回の振り返りカード（月曜始まり） | 週は日曜〜土曜（`buildWeeks`）。通知の仕組みも持たない。見る場所は目標タブで足りる |

## 9. トレーニングの側（2026-09-27 追加）

目標タブ（トレーニング）も、文字を減らして図で読む形にした。

| カード | 図 | 押すと |
| --- | --- | --- |
| 今週の量 | 日〜土の 7 つの点（やった日を塗る）と、部位ごとの縦の棒。棒の頭に「いま」のセット数（挙上量の目標だけの部位は挙上量）、下に部位名。縦の物差しは**目標に対する割合**で、目標の線は全部位で同じ高さの 1 本。線の名前は右端に 1 度だけ（全部位が同じセット数目標だけなら「目標 15」、それ以外は「目標」） | 部位の目標の面（セット数・挙上量の 2 つの欄、前回の日） |
| 種目の目標 | 1 行＝色の丸（部位）・名前・**いま / 目標 単位**。その下に 1 本の線：開始 ○ → いま ● → 最大 │ → 目標 ◆（`GoalTrack`）。開始より下は左の区間へ赤い点線ではみ出す。左の区間は全行に引いて開始の位置をそろえる。見出しに到達の輪。維持の種目は名前だけを下に並べる | **推移**（見出しの「閉じる」の左に「目標」。そこから目標の面、その中に「設定」） |

### 9.1 部位の目標はセット数と挙上量を同時に持てる

`GroupTarget` は `{ sets, volume }`（どちらか片方だけでもよい。両方 null なら目標ごと null）。
以前の `{ type, value }`・素の数値は読み込みで読み替える（版は上げない）。

- 今週の量の棒は**目標ごとに 1 本**。セット数は部位の色で塗り、挙上量は同じ色の斜線と枠（`volumeBarStyle`）。
  色は部位が使っているので、何を数えたかは模様で分ける。挙上量の目標が 1 つでもあれば、棒の下に模様の見方を出す。
- 物差しは割合なので、2 本とも同じ目標の線で読める。
- 目標の面では、片方の欄を空にすると**もう片方が残っているときだけ**その側を外す。最後の 1 つは「目標を外す」で。
- 打つ瞬間の波及行（`ExerciseRipple`）は 1 つの軸だけを見る：セット数の目標があればセット数、挙上量だけなら挙上量。
- 1 日あたりの提案（`suggestSetsPerDay`）はセット数の目標からだけ出す。

### 9.2 その他

- 「最大」は `ExerciseGoal.best`（これまでの最大。`current` と同じ物差し）。`current` は直近 1 回なので、軽めの日に大きく下がる。
- 前回の日（「最後にやってから ○日」）は棒の下には出さず、部位を開いた面だけに出す。
- 種目の目標は**部位ごとに見出しを付け、部位の中は名前順**（マイ種目の一覧と同じ）。見出しに部位の色の印。進み具合の順に並べると記録のたびに行が入れ替わり、同じ種目を探し直すことになるのでやめた。
- 目標の行は行ぜんたいを押す → **推移**。目標を決め直すのは推移を見てからのことが多いので、見る → 決めるの順に重ねる（`Modal` の `action`）。
- 「いま」は直近 1 回の値で、**記録のたびに動く**。到達したあとも目標の先へ進み、下がれば戻る。開始値が無い・目標が開始値以下で「開始 → 目標」の縮尺が取れない行は、開始・いま・最大・目標の範囲そのものを線に取る（以前は到達すると点が目標に貼り付いていた）。

## 10. 体組成の側の追加（2026-09-27）

- **推定1RM のカード（C）はやめた。**体組成の目標タブにトレーニングの値が出るのは場違いだった。
- 目標値の編集（目標体重・体脂肪率・目標日）は**ダイアログで開く**。カードの下に広げると、開くたびに下が押し下げられる。
- 目標の体組成の棒は**押すと内訳の吹き出し**（体重・除脂肪・脂肪・体脂肪率）。棒の中に数を全部書くと、細い脂肪の段に収まらない。
  除脂肪の差の赤字と、減る分を示した赤い点線の枠は外した（意味が読み取りにくかった）。いまの除脂肪の高さの点線は残す。
- **目標の開始日**（`Settings.startDate`）。開始値（開始比・進捗の起点）をその日からの最初の 7 個の実測で取る（`startValues`）。
  全計算と増分の両方が同じ関数を呼ぶ（片方だけ見ると画面ごとに開始比が割れる）。null なら記録の最初の日から。
  目標のカードの「開始」には日付も添える（「開始 9/1 74.1kg」）。ヒーローとタイルの開始比も同じ値から出る。
